# socsim Capability Map (for AI coding agents)

`socsim` (`rs-social-simulation-tools`) is a composable, **seed-deterministic** agent-based social-simulation platform in Rust, organised as a **nineteen-crate** workspace. This page is the curated **capability map** for an AI agent building an implementation — usually an academic-paper replication — **on top of** socsim consumed as a git dependency.

Three sources, three jobs:

- **This map** = the curated, task-oriented index: which crate to reach for, the exact import paths and signatures you actually call, and the rules you must not break.
- **`cargo doc -p <crate>`** = the full, authoritative API (everything; this map keeps only the load-bearing surface).
- **The human docs in `docs/*.md`** (`architecture.md`, `library.md`, `design.md`, `packs.md`, `mechanisms.md`, `cli.md`) = the prose, worked examples, and rationale.

> Companion file: **`docs/ai/recipes.md`** — copy-paste templates (`Cargo.toml` + `main.rs` skeletons per replication shape). Read this map for *what exists*; read recipes for *how to wire it*.

All git snippets below use:
`git = "https://github.com/akitenkrad/rs-social-simulation-tools"`, `branch = "main"`, `package = "<crate>"`.

## Mental model (read this first)

**One world, many mechanisms, six phases per tick.**

- A **`WorldState`** owns all shared state (agent roster + `SimClock` + your domain data). You implement it.
- A **`Mechanism<W>`** is one composable unit of research logic (the analogue of a neural-net layer). It declares which **`Phase`**s it runs in and mutates the world inside `apply`. You implement these.
- Each tick runs the **fixed 6-phase loop**, in this exact order (`socsim_core::Phase::ORDER`):

  ```
  PreStep → Environment → Decision → Interaction → Reward → PostStep
  ```

  Per phase, every mechanism that registered that phase fires in **insertion order**. (Verified: `crates/socsim-core/src/lib.rs` `Phase::ORDER`.)
- A **`Simulation<W>`** (built by **`SimulationBuilder<W>`**) drives the loop. A **`Scheduler<W>`** picks each step's agent activation order; a seeded **`SimRng`** (ChaCha20) supplies all randomness; a **`Recorder`** sinks metrics/events (default `NullRecorder` = no-op).

**Two usage modes (both first-class):**

| Mode | What you write | Crates you pull in | Used by |
|---|---|---|---|
| **(a) Library mode** | your own `main.rs` + clap CLI, `WorldState`, `Mechanism`s; drive `SimulationBuilder` directly | only the crates you need (`socsim-core`/`-engine`, optionally `-grid`/`-net`/`-mechanisms`/…) | **most replications** |
| **(b) CLI mode** | a `Scenario` TOML + a `ModulePack`; run via the `socsim` binary (the bundled `normal-form` pack needs only the TOML) | the `socsim` binary + a pack | bundled packs, sweepable scenario files, normal-form games without Rust |

**LLM-social replications** that have no spatial/ABM engine deliberately do **not** pull in `socsim-core`/`-engine`/`-net`; they depend on `socsim-llm` (+ `-results`/`-survey`/`-reproduce`/`-metrics`) only. **Spatial/ABM** replications use library mode with `socsim-core`/`-engine`/`-grid`/`-net`.

**Two-layer determinism.** The socsim core is **seed-deterministic and LLM-free**: same seed + same code ⇒ identical trajectory. The optional **`socsim-llm`** layer is made *cache-pseudo-deterministic* on top — LLM nondeterminism is confined to a prompt cache and, by convention, to the **`Decision`** phase (an LLM call is a synchronous `complete` inline in `Mechanism::apply`).

Minimal library-mode shape (signatures verified against `socsim-core` / `socsim-engine`):

```rust,ignore
use socsim_core::{AgentId, Mechanism, Phase, Result, SimClock, StepContext, WorldState};
use socsim_engine::{RandomActivationScheduler, SimulationBuilder};

let mut sim = SimulationBuilder::new(my_world)   // SimulationBuilder::new(world: W)
    .scheduler(Box::new(RandomActivationScheduler))
    .seed(42)                                     // default seed is 0
    .add_mechanism(Box::new(MyMechanism::new()))
    .build();
sim.run()?;                                       // or run_until / run_observed / step
let final_state = sim.world();
```

## Per-crate digest

> **Layer key:** *foundation* (no internal deps) · *engine spine* (the CLI/run stack) · *orthogonal + optional* (beside the engine) · *library-only leaves* (engine-free helpers).

### Foundation

#### `socsim-core`
- **Purpose:** the four composable traits + core types every other crate builds on.
- **Engine-free?** Yes. **Depends-on:** `socsim-rng` (re-exported).
- **Git dep:**
  ```toml
  socsim-core = { git = "https://github.com/akitenkrad/rs-social-simulation-tools", branch = "main", package = "socsim-core" }
  ```
- **Feature flags:** none.
- **Key public API** (all `socsim_core::…`, from `crates/socsim-core/src/lib.rs`):
  - `AgentId(pub u64)` — `Copy + Ord + Hash + serde`.
  - `SimClock::new(t_max: u64)` · `.t() -> u64` · `.t_max()` · `.is_done() -> bool` · `.tick()`.
  - `enum Phase { PreStep, Environment, Decision, Interaction, Reward, PostStep }`; `Phase::ORDER: [Phase; 6]`.
  - `trait WorldState: 'static` — `fn agent_ids(&self) -> Vec<AgentId>`; `fn clock(&self) -> &SimClock`; `fn clock_mut(&mut self) -> &mut SimClock`.
  - `trait Mechanism<W: WorldState>` — `fn name(&self) -> &str`; `fn phases(&self) -> &'static [Phase]`; `fn apply(&mut self, phase: Phase, ctx: &mut StepContext<'_, W>) -> Result<()>`.
  - `trait Scheduler<W: WorldState>` — `fn activation_order(&mut self, world: &W, rng: &mut SimRng) -> Vec<AgentId>`.
  - `trait Recorder` — `record_metric(&mut self, t: u64, key: &str, value: f64)`; `record_event(&mut self, t, kind: &str, payload: serde_json::Value)`; `record_row(&mut self, t, table: &str, row: &[(&str, f64)])` (default fans out to `record_metric`); `as_any(&self) -> Option<&dyn Any>`.
  - `struct NullRecorder` (the engine default sink).
  - `struct StepContext<'a, W>` pub fields: `world: &'a mut W`, `clock: SimClock` (a value copy), `rng: &'a mut SimRng`, `recorder: &'a mut dyn Recorder`, `agent_order: &'a [AgentId]`, `scratch: &'a mut Blackboard`, `stop: &'a mut bool`; method `request_stop(&mut self)`.
  - `struct Blackboard` — step-scoped, type-erased: `insert<T>(&mut self, key: &'static str, value: T)`, `get::<T>(key)`, `get_mut::<T>(key)`, `clear()`. Cleared by the engine at the start of every step.
  - `enum SocsimError` + `type Result<T> = std::result::Result<T, SocsimError>`.
  - **Capability traits** (in `socsim_core::opinion`, re-exported at crate root) — opt-in bounds that let `socsim-mechanisms`/`socsim-metrics` operate on any world:
    - `ScalarOpinions` — `opinion(id) -> f64` / `set_opinion(id, value)`.
    - `Neighbors` — `neighbors_of(id) -> Vec<AgentId>` (the influence set).
    - `BinaryState` — `is_active(id) -> bool` / `set_active(id, bool)`.
    - `CultureVectors` — `n_features() -> usize` / `feature(id, f) -> u32` / `set_feature(id, f, value)`.
    - `ActivationThreshold` — `activation_threshold(id) -> f64` (per-agent θ_i).
    - `GroupMembership` (+ `type GroupId = u64`) — partition structure for group dynamics.
- See `cargo doc -p socsim-core` for the rest.

#### `socsim-rng`
- **Purpose:** seeded, reproducible ChaCha20 RNG + label-based seed derivation.
- **Engine-free?** Yes. **Depends-on:** none.
- **Git dep:** usually unnecessary directly — `socsim-core` re-exports `SimRng` and `derive_seed`. If needed:
  ```toml
  socsim-rng = { git = "https://github.com/akitenkrad/rs-social-simulation-tools", branch = "main", package = "socsim-rng" }
  ```
- **Feature flags:** none.
- **Key public API** (`crates/socsim-rng/src/lib.rs`):
  - `SimRng::from_seed(seed: u64) -> SimRng` — the root RNG (impls `rand::RngCore`, `Clone`, serde).
  - `SimRng::derive(&self, label: &[u64]) -> SimRng` — child RNG from a label, without mutating `self`.
  - `derive_seed(root: u64, parts: &[u64]) -> u64` — the FNV-1a mix used by `derive`. Convention: `derive_seed(root, &[0])` = world init, `derive_seed(root, &[1])` = engine/scheduler.

### Engine spine

#### `socsim-engine`
- **Purpose:** the `Simulation` driver, `SimulationBuilder`, schedulers, snapshots.
- **Engine-free?** No (it *is* the engine). **Depends-on:** `socsim-core` (runtime). *(`socsim-config`/`-grid`/`-log`/`-net` are dev-only deps for examples.)*
- **Git dep:**
  ```toml
  socsim-engine = { git = "https://github.com/akitenkrad/rs-social-simulation-tools", branch = "main", package = "socsim-engine" }
  ```
- **Feature flags:** none.
- **Key public API** (`crates/socsim-engine/src/lib.rs`):
  - `SimulationBuilder::new(world: W) -> Self` → `.add_mechanism(Box<dyn Mechanism<W>>)` · `.scheduler(Box<dyn Scheduler<W>>)` · `.seed(u64)` · `.recorder(Box<dyn Recorder>)` · `.build() -> Simulation<W>`. **Defaults:** scheduler `SequentialScheduler`, seed `0`, recorder `NullRecorder`. (Verified.)
  - `Simulation<W>`: `run()` (until clock done **or** stop requested); `run_until<F: Fn(&W) -> bool>(predicate)`; `run_observed<F: FnMut(StepReport<'_, W>)>(observe)`; `step()`; `step_reported() -> Result<StepReport<'_, W>>`; `stop_requested() -> bool`; `world() -> &W`; `scratch() -> &Blackboard`; `recorder() -> &dyn Recorder`; `recorder_mut()`; `snapshot() -> Snapshot<W>` (`where W: Clone`); `restore(Snapshot<W>)`.
  - `StepReport<'a, W>` pub fields: `t: u64`, `stopped: bool`, `world: &'a W`, `scratch: &'a Blackboard`.
  - `Snapshot<W>` (`Serialize`/`Deserialize`): `save(path)` (`W: Serialize`), `Snapshot::load(path)` (`W: DeserializeOwned`); `SNAPSHOT_VERSION`.
  - `SequentialScheduler` (sorted `AgentId`) · `RandomActivationScheduler` (shuffled each step). These are the **only two** schedulers. (Verified.)

#### `socsim-config`
- **Purpose:** `Params` (typed TOML), `Registry` (mechanism factory), `ModulePack` trait, `Scenario` loader.
- **Engine-free?** Yes (deliberately, to avoid an engine→config→engine cycle). **Depends-on:** `socsim-core`.
- **Git dep:**
  ```toml
  socsim-config = { git = "https://github.com/akitenkrad/rs-social-simulation-tools", branch = "main", package = "socsim-config" }
  ```
- **Feature flags:** none.
- **Key public API** (`crates/socsim-config/src/lib.rs`, `scenario.rs`):
  - `Params::empty()`; `get_f64(key, default)` / `get_u64` / `get_i64` / `get_bool` / `get_str(key, default: &str) -> &str`. (Note: `get_i64` exists; there is no `get_string`.) `get_table(key) -> Option<Params>` (copy of a nested table; `None` if absent or not a table); `get_value(key) -> Option<&toml::Value>` (raw value, no conversion). `impl From<toml::Table>`.
  - **Typed getters return the default on a type mismatch, exactly as for an absent key:** `get_f64` reads only TOML floats (`rate = 2` → default), `get_u64` / `get_i64` only TOML integers (`n = 10.0` → default; `get_u64` maps `-1` to `u64::MAX`), `get_bool` / `get_str` likewise. To reject wrong types, read with `get_value` and check the variant yourself (as `socsim-games`' scenario reader does). There is no key listing (`keys`).
  - `Registry<W>::new()`; `register<F: Fn(&Params) -> Result<Box<dyn Mechanism<W>>> + 'static>(&mut self, name: &str, ctor: F)`; `build(name, &Params) -> Result<Box<dyn Mechanism<W>>>`; `names() -> Vec<&str>`.
  - `trait ModulePack<W>` — `pack_name(&self) -> &str`; `register(&self, reg: &mut Registry<W>)`.
  - `Scenario` (`from_path(&Path)` / `parse(text)` / `impl FromStr`; `validate(&self, registry_names: &[&str])`; `Serialize`, so `toml::to_string(&scenario)` round-trips through `parse`); sections `SimulationSection { name, module_pack, t_max, seed, scheduler }`, `world: RawParams`, `mechanisms: Vec<MechanismEntry>`, `output: OutputSection`.

#### `socsim-log`
- **Purpose:** concrete `Recorder` implementations.
- **Engine-free?** Yes. **Depends-on:** `socsim-core`.
- **Git dep:**
  ```toml
  socsim-log = { git = "https://github.com/akitenkrad/rs-social-simulation-tools", branch = "main", package = "socsim-log" }
  ```
- **Feature flags:** none.
- **Key public API** (`crates/socsim-log/src/lib.rs`):
  - `InMemoryRecorder::new()` — `metrics() -> &[MetricRow]`, `events() -> &[EventRow]`; supports `as_any` downcast.
  - `JsonlRecorder<W: Write>::new(sink)` — one JSON line per record; `take_error()`. *(Does not override `record_row` and does not support `as_any` downcast.)*
  - `CsvRecorder::new()` — `record_row`-aware; `set_columns(table, &[&str])` (pin header order), `table_csv(table) -> Option<String>`, `metrics_csv() -> String`, `tables()`, `events()`; supports `as_any` downcast.
  - Row types: `MetricRow { t, key, value }`, `EventRow { t, kind, payload }`.

#### `socsim-runner`
- **Purpose:** single/multi-seed runs, cross-seed summaries, parameter sweeps (rayon-parallel); trials built from the whole scenario by a `TrialFactory`, and checked sweeps.
- **Engine-free?** No. **Depends-on:** `socsim-core`, `socsim-config`, `socsim-engine`, `socsim-log` (plus `rayon`, `toml`).
- **Git dep:**
  ```toml
  socsim-runner = { git = "https://github.com/akitenkrad/rs-social-simulation-tools", branch = "main", package = "socsim-runner" }
  ```
- **Feature flags:** none.
- **Key public API** (`crates/socsim-runner/src/lib.rs`) — note American spelling **`summarize`**:
  - `type WorldFactory<W> = Box<dyn Fn(&Params, u64) -> Result<W> + Send + Sync>`.
  - `run_once(scenario, world_factory, register, seed) -> Result<RunResult>`.
  - `run_seeds(scenario, world_factory, register, seeds, parallel: bool) -> Result<Vec<RunResult>>`.
  - `summarize(results: &[RunResult]) -> Summary` (→ `Summary::to_csv()` / `to_json()`).
  - `run_sweep(scenario, axes: &[SweepAxis], world_factory, register, seeds: Vec<u64>, parallel) -> Result<Vec<SweepPoint>>`.
  - Data: `RunResult { seed, series, final_metrics, events, event_count }`, `MetricStats`, `Summary { metrics }`, `SweepAxis { param_key, values }`, `SweepPoint { params, summary }`.
  - **Trial factories** (`src/trial.rs`, `src/checked_sweep.rs`, re-exported at the crate root):
    - `#[non_exhaustive] struct Trial<W> { pub world, pub mechanisms: Vec<Box<dyn Mechanism<W>>>, pub scheduler: Box<dyn Scheduler<W>>, pub engine_seed: u64 }` — build with `Trial::new(world, mechanisms, scheduler, engine_seed)` (no struct literal outside the crate). The runner resets the world clock to `t_max` and always attaches its own `InMemoryRecorder`.
    - `trait TrialFactory<W>: Send + Sync { fn validate(&self, &Scenario) -> Result<()> /* default Ok */; fn build_trial(&self, &Scenario, seed) -> Result<Trial<W>>; }` — object safe.
    - `RegistryTrialFactory::new(world_factory: WorldFactory<W>, register: impl Fn(&mut Registry<W>) + Send + Sync + 'static)` — wraps the legacy pair; raw seed to world factory **and** engine (`run_trial` ≡ `run_once`); `validate` = `Scenario::validate(registry names)` (so `t_max = 0` errors here, not in `run_once`).
    - `scheduler_from_scenario(&Scenario) -> Result<Box<dyn Scheduler<W>>>` (`"sequential"` / `"random_activation"`).
    - `run_trial(scenario, &dyn TrialFactory<W>, seed) -> Result<RunResult>` — validate → build_trial → run.
    - `run_trials(scenario, factory, seeds: &[u64], parallel) -> Result<Vec<RunResult>>` — validate once; sorted by seed (stable); on failure returns the first failed seed **in input order** as `trial seed <s>: …`. No `W: Send` bound.
    - `run_trial_sweep(scenario, axes: &[SweepAxis], factory, seeds: &[u64], parallel) -> Result<Vec<CheckedSweepPoint>>` — keys `world.<a>[.<b>…]` (existing `[world]` key, nested tables) or `<mechanism>.<param>` (every entry with that name); existing integer stays integer (integral values only), existing float stays float, other types / non-finite values / unknown `world.` path / unknown mechanism / duplicate or empty axis → `SocsimError::Config("sweep axis '<key>': …")`; a missing `<param>` is added as a float. Every grid point is patched and `validate`d before any trial runs (`sweep combination [k=v, …]: …`).
    - `#[non_exhaustive] struct CheckedSweepPoint { params, effective: Scenario, summary }` (`Serialize`/`Deserialize`).

#### `socsim-cli` (binary `socsim`)
- **Purpose:** the world-polymorphic `socsim` binary wrapping packs + runner.
- **Engine-free?** No. **Depends-on:** `socsim-core`/`-config`/`-engine`/`-log`/`-runner`/`-datasets`; `socsim-packs` (optional).
- **Consume as:** the **binary** (`cargo build --release` → `target/release/socsim`), not a library dep. Replications generally use library mode instead.
- **Feature flags** (default on: `pack-hr-lifecycle`, `pack-opinion-dynamics`, `pack-organizational-silence`, `pack-normal-form`):
  | Feature | Gates |
  |---|---|
  | `pack-hr-lifecycle` / `pack-opinion-dynamics` / `pack-organizational-silence` | the three registry-based bundled `CliPack`s |
  | `pack-normal-form` | the `normal-form` `CliPack` (`socsim-packs/normal-form`: `NormalFormPack` over `socsim-games` scenarios) |
  | `pack-organizational-silence-llm` | opt-in LLM voice-decision in the silence pack |
  | `datasets-acquire` | enables `socsim-datasets/acquire` for the `datasets` subcommand |
- **Subcommands:** `init --module-pack <PACK> -o <PATH>` · `run <scenario> [--seeds A..B] [--parallel]` · `validate <scenario>` · `list <packs|mechanisms>` · `sweep <scenario> --param MECH.PARAM=v1,v2 [--seeds 0..5] [-o runs/sweep] [--parallel]` (`normal-form` also takes `world.<path>=v1,v2`) · `summarize <path> [--format csv|json]` · `datasets <subcommand>`.
- **`CliPack` (trait in the binary crate's `src/packs.rs`; not a library API):** `name`, `starter_toml`, `mechanism_names` (sorted), `validate(&self, &Scenario) -> anyhow::Result<()>` (pack-specific check; default `Ok(())`), `run_seeds`, `run_sweep`, `run_sweep_rows` (default wraps `run_sweep` with `effective: None`).
- **Validation order (all of `validate`, `run`, `sweep`):** load → `dispatch(module_pack)` → `Scenario::validate(&mechanism_names)` (`t_max > 0`, scheduler `sequential`/`random_activation`, registered names) → `CliPack::validate`; the second is skipped if the first fails. Failure → `validation failed for '<path>'` + cause, exit 1, **before** `Running …`/`Sweeping …`, any trial, the output directory or any file. Consequence for the registry-based packs: valid scenarios behave as before, invalid ones (e.g. `t_max = 0`, which used to run 0 steps) are now rejected by `run`/`sweep` too. `sweep` validates the **base** scenario, so it must be valid itself.
- **Sweeps:** `normal-form` overrides `run_sweep_rows` with `run_trial_sweep` (`world.<path>` axes, unknown path / mechanism / non-numeric target / fractional value for an integer key → `sweep axis '<key>': …`; every combination validated before any trial → `sweep combination [k=v]: …`) and writes `combo_{i:04}_{label}.scenario.toml` (the effective scenario, `toml::to_string`) next to each CSV. The registry-based packs keep the legacy `run_sweep`: unknown keys are silently ignored, no `.scenario.toml`. Labels are `{k}={v:.4}`, so tiny values collapse (`1e-9` → `0.0000`); read the effective scenario.

  - Rules: `trait DecisionRule<G, X> { fn name(&self) -> &str; fn init_state(&self, &RuleInitContext, &G) -> Result<X::PolicyState, RuleError>; fn decide(&self, state: &mut X::PolicyState, &DecisionContext<G, X>, &mut SimRng) -> Result<G::Action, RuleError>; fn learn_step(&self, state, &LearnContext<G, X>) -> Result<(), RuleError> /* default no-op */; fn learn_encounter(&self, state, &EncounterOutcome<G::Action>, &LearnContext<G, X>) -> Result<(), RuleError> /* default no-op */; fn needs_encounter_learning(&self) -> bool /* false; true ⇒ learn_encounter is called */; fn needs_pair_history(&self) -> bool /* false; true for any assigned kind ⇒ build_world creates the pair history */; fn mixed(&self, &X::PolicyState, role, &G) -> Option<Vec<f64>> /* None; the next-step mix, read-only, no RNG; called only with report_mixed */; }`. Built-ins: `Fixed::new(action)` (needs `Slot<Stateless>`), `UniformRandom` (`FiniteGame`, `Slot<Stateless>`), `TitForTat::new(coop)` (`FiniteGame`, 2 roles × 2 actions, `Slot<TftState>`; one global `last_opponent`, unchanged).
  - Learning rules (feature `core`; all `FiniteGame`; every check runs in `init_state` → `build_world` fails with `GameError::Rule(RuleError::Unsupported(_))`):

    | Rule | Constructor | Slot / `BuiltinPolicyState` variant | Rejected at build time unless |
    |---|---|---|---|
    | `Mixed` | `Mixed::new(q)` | `Stateless` / `Stateless` | `q` finite, `>= 0`, `\|Σq − 1\| <= 1e-12`, `q.len()` == action count of **every** role |
    | `MyopicBestResponse` | `::new().tie_break_lowest() \| .tie_break_random().first_action(a /* 0 */)` | `Stateless` / `Stateless` | `a` valid for every role. `needs_pair_history() = true`. `PerStep`: best response to current opponents' previous-step actions (step history); `PerEncounter`: to the last pair-history action of that encounter's opponent; `PerAgentRole`: expected-payoff best response to the uniform mix of the last pair-history action of each current opponent that has a record. No applicable action → `first_action`. Non-`PerStep` scope with ≠ 2 roles → `RuleError::Unsupported` at decide time |
    | `FictitiousPlay` | `::new().initial_counts(vec /* zeros */).tie_break_lowest() \| .tie_break_random()` | `BeliefState` / `Belief` | 2 roles; counts finite `>= 0`, length == opponent's action count for both roles |
    | `LogitChoice` | `::new(lambda).estimate(EstimateMode::{LastOpponent, EmpiricalFrequency /* default */})` | `EstimateState` / `Estimate` | 2 roles; `lambda` finite `>= 0` |
    | `RothErev` | `::new(phi, epsilon, initial_propensity)` | `PropensityState` / `Propensity` | `0 <= phi < 1`, `0 <= epsilon < 1`, `initial_propensity > 0`; every payoff of every role/profile finite `> 0` |
    | `Automaton` | `::new(AutomatonKind::{AllC, AllD, Grim, Wsls, Tft, Gtft { generosity }}, coop)` | `AutomatonPolicyState` / `Automaton` | every role has exactly 2 actions; `coop ∈ {0, 1}`; `generosity ∈ [0, 1]` |

    `BeliefState` / `EstimateState` / `PropensityState` / `AutomatonPolicyState` expose `global()` and `by_opponent() -> &[(AgentId, _)]` (ascending `AgentId`); `BuiltinPolicyState` implements `Slot<_>` for all of them.
  - Learning cores (default build, `socsim_games::learn`; no `socsim-*` dep; take `&mut dyn RngCore`): `fictitious::{FictitiousBelief::{new(&g, role, initial_counts, TieBreak), with_defaults(&g, role), counts() /* incl. initial pseudo-counts */, empirical_counts() /* observations only */, best_response, observe}, simultaneous_step(&g, &mut b0, &mut b1, rng)}` (no alternating variant); `roth_erev::RothErevState::{new(&g, role, q0, phi, epsilon), propensities, selection_probabilities, choose_action, update(chosen, payoff), update_from_profile}` (`q_j ← (1−φ)q_j + E_j`, `E_k = (1−ε)x` for the chosen action, `εx/(N−1)` for the others; no reference point); `logit::LogitState::{new(&g, role, lambda, EstimateMode), with_default_mode, observe, expected_payoffs, selection_probabilities /* max-subtracted softmax; uniform before any observation or at λ = 0 */, choose_action}`; `automaton::{AutomatonState::{new(kind, coop), next_action, observe(own, opponent)}, validate_two_action_game}`; `sample_probabilities(&p, rng)` (one `gen::<f64>()`, cumulative walk in index order), `resolve_tie(&candidates, TieBreak::{LowestIndex /* default, no RNG */, Random /* one gen_range */}, rng)`; errors `LearnError`. `RuleBook::new()` + `register(kind: &str, Arc<dyn DecisionRule<G, X>>)`; kind ids follow sorted kind-name order. `RuleInitContext { agent, kind, generation, init_seed }`.
  - Experiment state: `trait ExperimentState { type PolicyState: Clone + Send + Sync + Debug; type View<'a>; fn view_for(&self, me: AgentId) -> Self::View<'_>; }`; `impl ExperimentState for ()` (`PolicyState = BuiltinPolicyState`, `View = ()`). `trait Slot<T> { slot, slot_mut, from_slot }`; `BuiltinPolicyState::{Stateless, TitForTat, Belief, Propensity, Estimate, Automaton, Continuous}` (+ `Llm` under `llm`; `#[non_exhaustive]`) implements `Slot<Stateless>`, `Slot<TftState>`, `Slot<BeliefState>`, `Slot<PropensityState>`, `Slot<EstimateState>`, `Slot<AutomatonPolicyState>`, `Slot<ContinuousState>`.
  - Outcome: `trait OutcomeRule<G, X> { fn name(&self) -> &str; fn outcome(&self, &OutcomeContext<G, X>, EncounterRef, actions: &[G::Action], payoffs: &mut [f64]) -> socsim_core::Result<()>; }`; built-in `NormalFormOutcome` (`G: NormalFormGame`). `OutcomeContext::{t, game, x, held(agent), topology}`. `Credit::{All /* every seat credited */, Center /* only seat 0 credited (payoff + n_played); used by GridNeighborhood */}`; the arena keeps every seat's payoff and `played_share` counts every seat regardless of credit.
  - Matching: `trait Matching<G, X> { fn name; fn check(&self, &MatchContext) -> Result<(), GameError>; fn supports_roles(&self, n) -> bool /* n == 2 */; fn encounter_bounds(&self, &MatchContext) -> Option<EncounterBounds { min, max }> /* None; encounters credited per agent per step */; fn allows_multi_role_per_step(&self) -> bool /* false */; fn implicit(&self) -> Option<ImplicitPattern::{GridCenter { include_self }, NetworkEdges, WholePopulation}> /* None */; fn init_state(..) -> MatchingState /* None */; fn encounters_into(&self, &MatchContext, &mut MatchingState, &mut SimRng, &mut ArenaWriter<G::Action>) -> socsim_core::Result<()>; }`; `MatchContext::decision_scope() -> DecisionScope` (for `check`); `ArenaWriter::push(&[AgentId], Credit) -> Result<EncounterId>`; built-in `FixedPlayers::pairs(&[(u64, u64)])` / `FixedPlayers::new(Vec<[AgentId; 2]>)`; `RoundRobin::new().both_orders(bool /* false */).self_play(bool /* false; true rejected */)` — every pair of sorted ids once per step in lexicographic order, lower id in role 0, reversed pair immediately after with `both_orders`; no RNG; state `MatchingState::RoundRobin { cursor }` (+1 per step); `check` → `InvalidMatching` for ≠ 2 roles, self-play, or `PerStep` with ≥ 3 agents or `both_orders(true)`. Population matchings: `RandomPairs::new()` (2 roles; one shuffle per step; odd n → one agent sits out; bounds `1..1` / `0..1`), `RandomGroups::new(k)?` (`k ≥ 2` else `InvalidMatching`; k roles = `n_roles`; one shuffle; last `n mod k` sit out), `WholePopulation::new()` (one encounter, seats in `AgentId` order, `n_roles` must equal agent count; implicit; no RNG), `NetworkEdges::new()` (feature `net`; 2 roles; one encounter per sorted dedup edge `(source, target)`, `Credit::All`; needs `Topology::Network`; multi-role; implicit; no RNG), `GridNeighborhood::new().include_self(bool /* false */)` (feature `grid`; per cell in index order, `[center, neighbour]` per sorted neighbour then `[center, center]` with self-play, `Credit::Center`; needs `Topology::Grid`; multi-role; implicit; no RNG). A matching with `allows_multi_role_per_step()` lets a rule-driven agent hold several roles under `PerStep`: one decision, played in every seat; `opponents()` = union over its seats.
  - Decision scope: `PlayOptions::decision_scope(DecisionScope::{PerStep /* default */, PerAgentRole, PerEncounter})`. `PerStep`: one `decide` per agent per step (`DecisionUnit::Step`), written to all its seats and to `held`; `role/encounter/opponents` from its last seat. `PerAgentRole`: one per role held (ascending; `DecisionUnit::AgentRole(role)`, `encounter() = None`, `opponents()` = deduplicated union over that role's encounters). `PerEncounter`: one per seat in `EncounterId` order (`DecisionUnit::Encounter(id)`). The two finer scopes do **not** write `held` and record `StepRecord::action = None`. `Held` agents fill all their seats with `held` under every scope.
  - Views: `DecisionContext::{t, me, unit, scope, role, encounter, opponents, my_history, my_held() /* own held action before this decision */, opponent_history(id) /* None unless id is a current opponent */, pair_history(id) -> Option<PairView> /* None unless enabled and id is a current opponent; empty view if never met */, aggregate_history() -> Option<AggregateView> /* None unless assemble_with_aggregates; completed previous steps only */, game, view, omniscient}`; `LearnContext::{t, me, scope, record, my_history, outcomes /* EncounterId order */, game, view, omniscient}`; `OmniscientContext::{ids, held(agent), history(agent), pair_history(a, b) /* only via DecisionContext::omniscient; None via LearnContext */, x}`; `PairView::{len, is_empty, iter() -> (t, &my_action, &other_action) oldest first, oriented to the asker}`.
  - World: `GameWorld<G, X = ()>` (`WorldState`; serde when `G`, `G::Action`, `X`, `X::PolicyState` are) — accessors `game()`, `x()`, `x_mut()`, `held()`, `policies()` (`PolicyTable::{state(agent), kind(agent)}`), `plays()` (`PlayArena`), `payoffs()` / `n_played()` (**this step only**), `history(agent)` (`HistoryView<StepRecord { action: Option<A>, payoff, n_played }>`), `reported_mixed(agent, role) -> Option<&[f64]>` (post-learning mix written at the end of Reward; `None` unless `report_mixed`). Optional world fields, each omitted from the world JSON when absent and carried by snapshots: `aggregate` (aggregate ring), `reports` (mixed reports), `metrics_state` (`game_metrics` convergence / cumulative state). Pair history: ring of `history_len` records per unordered pair, created by `build_world` only if some assigned kind returns `needs_pair_history() == true` (among built-ins only `MyopicBestResponse` does); appended by `game_play` for two-seat encounters after payoffs; field `pair_history` omitted from the world JSON when absent.
  - Kinds: `KindCatalog::new().with_rules(&RuleBook)?.with_llm(&LlmRuleBook)?` (feature `llm` for `with_llm`) / `KindCatalog::from_rules(&rules)` — the single registry of every kind across drivers; a kind in two books → `RuleError::DuplicateKind`; kind ids = sorted union of names; `kinds()`, `kind_id(kind) -> Option<RuleKindId>`, `driver_name(kind) -> Option<&'static str>` (`"game_decide"` / `"game_llm_decide"`). `build_world_with(game, n_agents, x, initial_held, &catalog, &assign, history_len, t_max, seed)`; `build_world(.., &rules, ..)` ≡ `build_world_with(.., &KindCatalog::from_rules(&rules), ..)`. `assemble` rejects a world whose kind list ≠ its `RuleBook`'s (`GameError::InvalidKinds { expected, actual }`); `game_decide` skips kinds it does not own.

  - Initial actions (feature `core`): `InitialActions::Shares(Vec<(A, f64)>)` — exact counts by largest remainder (ties → pair listed first), laid out in the **listed order** then shuffled with `derive_seed(seed, &[0, 2])` (independent of `Assignment::Shuffled`'s `[0]`); shares finite, ≥ 0, sum 1 ± 1e-9, each action valid for every role, no action twice (`GameError::Config`; `GameError::Action` for an invalid action). Every solver first rejects 0 roles, an empty action set, > 10^6 profiles (`TooLarge`) and non-finite payoffs. Every equilibrium-returning solver recomputes the regret on the original game and returns only if `regret <= tol`. `Equilibrium { strategies: Vec<MixedStrategy>, payoffs, regret }` + `is_pure()`.

    |---|---|---|---|

    | `support_enumeration(&g)` | 2 | `EquilibriumSet { equilibria, findings: Vec<SupportFinding::{Degenerate, Component { base, directions }, Inconclusive}> }`; `is_complete()` = no findings | all NE for nondegenerate games; degenerate / ill-conditioned (cond > 1e12) supports go to `findings`, never fabricated (`Component.base` is verified and also in `equilibria`); `(2^m-1)(2^n-1) <= 2^20` (10×10 ok, 11×10 → `TooLarge { profiles: <pair count> }`); f64, no exact rationals |

    | `maximin_security_level(&g, role)` | 2 (any payoffs) | `SecurityLevel { level, strategy, duality_gap }` | same LP pair + checks on `role`'s own matrix; `role >= 2` → `InvalidOptions`; a guarantee, not an equilibrium strategy |

    | `replicator_fixed_points(&g)` | 2, symmetric | `FixedPointSet { isolated: Vec<FixedPoint { support, point }>, components: Vec<AffineComponent { support, base, directions }>, inconclusive: Vec<Vec<usize>> }` | indifference equations on every support; rest points, not necessarily NE (every pure strategy is one); ≤ 20 actions |
    | `ess_verdict(&g, &resident)` | 2, symmetric | `EssVerdict::{True, False, Inconclusive}` (`#[non_exhaustive]`) | not a symmetric NE → `False`; best responses = support → sign of the tangent-space quadratic form (eigenvalues); else cone check for ≤ 3 best responses; near-zero → `Inconclusive` |
    | `logit_qre(&g, &QreOptions)` | n | `QreSolution { lambda, strategies, residual, regrets, iterations }` | damped fixed-point iteration from `init` (default uniform); defaults `damping 0.1`, `tol 1e-12`, `max_iter 100_000`; returns only if recomputed residual ≤ `tol`, else `NotConverged { residual, iterations }`; **local, not principal-branch tracking** (different `init` → possibly different QRE); for large λ lower damping or step λ up passing the previous solution as `init`; `lambda == 0` → uniform; ordinary regret ≤ `ln\|S_i\|/λ` at an exact QRE (reported, not enforced) |

- **Limits today:** the role count must be supported by the matching (`supports_roles`; two except `RandomGroups(k)` / `WholePopulation`), for `assemble_with_llm` too (`UnsupportedRoles`); population dynamics support `Update::Synchronous` through `assemble_with` and `Update::Asynchronous` only through `assemble_async` (implicit matchings — grid, network, whole population — only; no `MoranUpdate`; no `RandomPairs` / `RandomGroups`), only held agents, finite games or — except `replicator_update` — continuous games, and never mix with decision rules; `MatchingState` has only `None` and `RoundRobin { cursor }` (custom matching state goes in `X`). Learning rules: fictitious play and logit choice are **two-player only** (so is `MyopicBestResponse` under `PerAgentRole` / `PerEncounter`); Roth–Erev requires **strictly positive payoffs** (shift the game; no reference-point variant) and a positive realised payoff at every update; automata require **exactly two actions** per role; fictitious play has no alternating-update variant. An agent that holds **both roles** of a game whose roles have **different action counts** gets **one global learning state shaped for role 0** under `PerStep` / `PerAgentRole` (under `PerEncounter`, each per-opponent state is shaped for the role of the first meeting) — decisions in the other role can fail; explicit `FictitiousPlay::initial_counts` and `Mixed` probabilities effectively require equal action counts. Built-in `TitForTat` keeps one global `last_opponent` in every scope (use `Automaton(Tft)` + `PerEncounter` for per-opponent TFT). `RoundRobin` has no self-play. LLM decisions: `PerStep` only. LLM rules in scenario TOML / the CLI, LLM replies for multi-dimensional continuous actions (`NumberParser` is 1-D only; `DescribedRenderer`'s multi-dim wording is provisional), and replaying past turns into the prompt are not provided. Metrics: `GameMetrics` needs `G: FiniteGame` (continuous games use `ContinuousMetrics`: mean / SD of actions, payoffs, aggregates, `eq_distance` only); `EquilibriumTarget::Solve` is two-player only and rejects degenerate games (incomplete equilibrium set); `report_mixed` is not available under `PerEncounter`; `Fixed`, `MyopicBestResponse` and LLM kinds report no mix (so `MixedSource::Reported` fails if they are seated); `action_entropy` only for pooled ids; `population_share` needs equal action counts per role; aggregates have no LLM-assembly variant (`assemble_with_llm` → `aggregate_history()` is `None`) and are not readable from `LearnContext` or a custom mechanism (only through `DecisionContext` and the `game.aggregate.*` columns). Solvers: `support_enumeration` / `lemke_howson` / `zero_sum_minimax` / `maximin_security_level` are 2-player only; `support_enumeration` is capped at 2^20 support pairs (≤ 10×10) and uses f64 (no exact rational arithmetic); dominance is pure-strict only; `logit_qre` finds a local fixed point at one λ (no homotopy / branch tracking); no solver for extensive-form games. Continuous games: only damped best-response iteration (one equilibrium per `x0`); the numerical best response covers only 1-D actions declared `Unimodal1D` and locates the maximum only to ~√ε·|x| (hence the relaxed default tol `1e-7` on that path); multi-dimensional games need an analytic `best_response` or a `BestResponseOracle`; games whose roles have different dimensions work with the solver but cannot be built into a world (`build_world` checks every initial action, and assembly every fallback action, against every role), so the per-role `ContinuousMetrics` columns are not recorded today; a world that bypasses these checks (deserializing a `GameWorld`, `Simulation::restore`) is not supported; `Fitness::Linear` and `ProportionalImitation` are unavailable for continuous games. Scenarios (`config`): built-in games / rules / matchings / dynamics only — no custom game, outcome rule or matching (counting play only via `game_play.counting` for the anonymous built-in kinds), no `OnInvalidAction::Fallback`, no `fixed` / `mixed` / LLM rules (register your own `DecisionRule`s with `RuleRegistry::register`); `X = ()` unless `GameTrialFactory::with_state`; `update = "synchronous"` only; `random_groups(k)` × `minority` / `el_farol` cannot be written (players = `n_agents`); undirected networks only; unknown **top-level** tables (`[game]`, `[matching]`) are silently dropped by `socsim-config` — only keys under `[world]` / `[[mechanism]]` are checked; `run_trial_sweep` keeps an existing integer an integer, so write sweepable reals as floats (`temptation = 5.0`). Examples: `crates/socsim-games/examples/ipd_pair.rs`, `crates/socsim-games/examples/ipd_tournament.rs` (round-robin IPD of automata under `PerEncounter`), `nowak_may.rs` (`--features core,engine,grid`; spatial PD, `ImitateBest`, prints `generation,cooperator_share` CSV), `huberman_glance.rs` (`--features core,engine,grid`; asynchronous `ImitateBest` with `UniformWithReplacement` vs the synchronous control, `--update async|sync`), `hawk_dove_large.rs` (`--features core,engine`; `RandomPairs` × `ProportionalImitation`, `--n 1000000` supported), `cournot.rs` (`--features core,engine`; damped best response of three Cournot firms); LLM usage: `crates/socsim-games/tests/llm_*.rs`.

### Library-only leaves (engine-free helpers)

#### `socsim-results`
- **Purpose:** the `results/<timestamp>/` + `latest`-symlink output convention, no `Recorder` needed.
- **Engine-free?** Yes — **no `socsim-*` deps** (`std`/`serde`/`serde_json`/`csv`/`chrono`).
- **Git dep:**
  ```toml
  socsim-results = { git = "https://github.com/akitenkrad/rs-social-simulation-tools", branch = "main", package = "socsim-results" }
  ```

## Invariants & anti-patterns

**Determinism**
- **All randomness via `SimRng`** seeded from the run seed. Never introduce an ad-hoc RNG (no `Math.random`-style global, no `rand::thread_rng()` in model code). Derive independent streams with `SimRng::derive(&[…])` / `derive_seed(root, &[…])`.
- **RNG stream convention:** `derive_seed(root, &[0])` = world/network/agent init, `derive_seed(root, &[1])` = the engine/scheduler (passed to `SimulationBuilder::seed`). Reserve `&[2]`, `&[3]`, … for further independent streams. **In a `socsim-games` simulation `&[2]` (`decision_root`) and `&[3, agent, generation]` (rule-state init) are taken**, and under `&[0]` the sub-streams `&[0, 1]` (scenario random network) and `&[0, 2]` (`InitialActions::Shares` layout, `uniform_initial_actions`) — start your own labels at `&[4]`.
- **Sorted `AgentId`.** `WorldState::agent_ids` should return IDs in sorted order; never let hash-map iteration order influence results.
- **LLM nondeterminism stays in `socsim-llm`.** A warm `PromptCache` + `LlmConfig::deterministic()` (temperature 0) is what makes an LLM run pseudo-deterministic on top of the seed-deterministic core. Keep model calls out of every phase except `Decision`. In `socsim-games` the same role is played by `ResponseStore` (`ReplayOnly` / `RecordMisses`) plus the manifest in `WithLlm<X>`.

**Engine-free boundaries** — do not regress these. `socsim-survey`, `socsim-results`, `socsim-reproduce`, `socsim-metrics` (default features), and `socsim-datasets` pull in **no engine crates**. Do not add `socsim-engine`/`-runner`/`-log` deps to these to keep LLM/survey replications lightweight. `socsim-config` is intentionally engine-free (avoids an engine↔config cycle).

**Keep paper-specific code OUT of socsim-\*.** Canonical, reusable things belong in socsim; anything with a *model-specific meaning* stays in the replication crate:
- A statistic with a paper-specific definition (e.g. a polarization measure defined as a product of extreme-opinion fractions, or a domain-event cascade aggregation) stays local — `socsim-metrics`' own guidance is *"keep paper-specific metrics local"* (reuse it only for canonical stats like `mean`/`variance`/`gini`).
- A survey recode is data, not code: encode it as a `SurveySchema`, not a hard-coded function.
- `socsim-reproduce` ships **no anchor values** on purpose — the paper's reference numbers live in the paper's crate as its own `&[Anchor]`.

**Phase semantics** — put logic in the phase whose meaning matches:
- `PreStep` — reset per-step counters / bookkeeping.
- `Environment` — exogenous shocks, resource replenishment, learning curves.
- `Decision` — agent decisions (incl. the **single** allowed home for LLM `complete` calls).
- `Interaction` — peer effects, network diffusion, contagion.
- `Reward` — compute/apply rewards, record aggregate metrics.
- `PostStep` — **read-only recording / convergence checks** (e.g. `MetricsMechanism` records here; `ctx.request_stop()` on convergence). Treat `PostStep` as the observation point, not a place to mutate dynamics.
- Snapshot (synchronous) vs asynchronous updates change the dynamics — snapshot the eligible set at step start for synchronous semantics; act on whoever is currently eligible for asynchronous. Choose deliberately.

**`socsim-runner` specifics**
- **Legacy `run_sweep` silently ignores what `run_trial_sweep` rejects.** `run_sweep` patches only `[[mechanism]]` params, always as floats, and silently skips a key without `.` and an unknown mechanism name (a typo such as `drfit.step` runs the unpatched scenario at every point, no error). `run_trial_sweep` returns `SocsimError::Config` for these, for unknown `world.` paths and for type mismatches. Neither catches a misspelt `<param>` (a missing param is added as a float) — reject unknown params in `TrialFactory::validate`. `run_sweep` is unchanged and the registry-based bundled `CliPack`s (HR / opinion / silence) still use it; the `normal-form` `CliPack` uses `run_trial_sweep` (its `validate` also rejects a misspelt `game_decide.<param>`, but not a valid key that no assigned rule reads).
- **`RunResult::seed` is the caller's trial seed**, never `Trial::engine_seed`.
- **A `Trial` never crosses threads.** `run_trials` / `run_trial_sweep` share only the factory (`Send + Sync`) and build each trial on the thread that runs it, so `W` need not be `Send`. Do not build trials up front and hand them to workers.
- **Engine seed convention.** A new `TrialFactory` should seed world init from `derive_seed(seed, &[0])` and return `engine_seed = derive_seed(seed, &[1])`, so its trajectories match a library-mode `main` that follows the same convention. `RegistryTrialFactory` deliberately uses the raw seed for both (bit-for-bit compatible with `run_once`).
- **`world.` is reserved by the sweep-key syntax only.** A mechanism may be registered as `world`, but its params cannot be swept (`world.<x>` always means `[world]`).
- **New runner errors are `SocsimError::Config(String)`** (no new error variants); match on the axis key in the message, not on the exact wording.

**`socsim-llm` specifics**
- Blank (whitespace-only) completions are **rejected by default** as `LlmError::EmptyResponse { endpoint, model }` (a reasoning model can spend its whole budget on a hidden trace). Opt out per call via `LlmConfig::allow_blank()`.
- Token-level logprobs come from `complete_with_logprobs` (default impl returns `LlmError::Unsupported`; live backends override it).
- Prefer the harness (`build_live_client_from_settings` / `wrap_client` / `llm_config`) over a per-model `llm.rs`.
- **`cache_key` covers `prompt` + `model` only.** `PromptCache` does not distinguish `system`, `seed`, `temperature`, `max_tokens` or `think`, and a hit drops `thinking` / usage. Do not vary those across calls that share one cache; for game simulations use `socsim_games::llm::ResponseStore`, whose `CacheKeyV1` includes them.
- **Parse with the shared helpers** (`parse_json_object`, `single_fenced_payload`, `parse_integer_value`, `json_field_was_string`, `extract_first_choice`) instead of re-implementing fence stripping or digit-string checks per replication.
- `build_live_backend` has **no cache**: wrap it (`wrap_client`) or record responses yourself; never put a caching client behind `socsim_games::llm::BackendFactory`.

**`socsim-games` specifics**
- **State needed to resume lives in the world; mechanisms are stateless.** Every agent's rule state is in `GameWorld`'s `PolicyTable`, the matching state in `MatchingState`, and everything model-specific in `X`. `game_match` / `game_decide` / `game_play`, the `RuleBook`, the `Matching` and the `OutcomeRule` are code re-supplied on rebuild. Never keep mutable per-run data in a rule, matching or outcome struct (`decide`/`learn_step` take `&self` for this reason) — it would not be in the snapshot and a resumed run would diverge. Keep `X` and `PolicyState` serde-restorable (no clients, handles, caches).
- **RNG streams `[2]` and `[3]` are reserved** (`derive_seed(seed, &[2])` = `decision_root`, `derive_seed(seed, &[3, agent, generation])` = `RuleInitContext::init_seed`), on top of the standard `[0]` (world init, `Assignment::Shuffled`) and `[1]` (engine; `decide` and `Matching` draw from the step RNG). Pass the same `seed` to `build_world` and `assemble`.
- **`DecisionRule` ≠ `socsim_marl::Policy`.** A `DecisionRule<G, X>` is a game-layer strategy over `G::Action` whose per-agent state is stored in the world and which is driven by `game_decide`; `socsim_marl::Policy` is a neural policy over an `f32` observation vector driven by `PolicyMechanism`. Do not wrap one as the other implicitly.
- **The core does not depend on `socsim-llm`** (nor `socsim-config` / `socsim-runner`). `socsim-llm` enters only through the optional `llm` feature and `socsim-config` / `socsim-runner` only through `factory` / `config`; do not add them to `socsim-games`' `core` / `engine` features, and do not reference `socsim_games::llm` types from `core` code (`GameWorld` knows nothing about LLMs — the manifest lives in `X` via `WithLlm<X>`).
- **Visualization stays across the Rust/Python boundary.** Only feature `export` writes the visualization JSON files; `core` uses `serde_json` only for event payloads and must not grow an implicit artifact writer. Drawing belongs only to `socsim_tools.games`. In a runvault run, write `artifacts/socsim_games/{game_spec.json,solutions.json}` before finishing the run, but save rendered figures outside the immutable run directory through `runvault.read.figures_dir`.
- **`GameSimFactory` and `GameTrialFactory` build through one procedure.** `GameTrialFactory::build_trial` reads the scenario into a `GameSimFactory` configuration and calls `GameSimFactory::build_trial`; do not add a second build path (e.g. "factory + scenario overrides"). Same configuration + same seed ⇒ identical world JSON and metric rows per step in both modes; `engine_seed = derive_seed(seed, &[1])`.
- **Scenario values never fall back to defaults.** The `socsim-games` scenario reader reads `RawParams.0` directly (not the `Params` getters): wrong types, out-of-range values and unknown keys (in `[world]`, `[world.game]`, `[world.population]` and every `[[mechanism]]` table) are `GameError::Config` with the key path; integers use the count rule (integral float ok). A user rule's keys must be declared in `RuleRegistry::register(name, keys, ctor)` or they are unknown keys.
- **LLM invariants (`llm` feature).**
  - The model is called **only inside `game_llm_decide`'s Decision phase** (`LlmDriver`). `prepare` is a pure render (no RNG, read-only state); `learn_step` (Reward) never calls the model.
  - **Seeds come from the decision unit, never from the engine stream.** Generation seed: `derive_seed(decision_root, &[0])` at temperature 0, else `derive_seed(decision_root, &[t, agent, 0, 0, attempt])`; fallback RNG: `derive_seed(decision_root, &[t, agent, 0, 0, u64::MAX])`. The driver does not touch `ctx.rng`, so activation order and worker count cannot change results (`Sequential` ≡ `Threaded`).
  - **Only the main thread writes to the `ResponseStore`.** Worker threads build their own cache-free backend from the `BackendFactory` and return replies; resolution happens in decision order.
  - **Every kind belongs to exactly one driver** (`KindCatalog`); build worlds with LLM kinds via `build_world_with` and assemble them via `assemble_with_llm` (plain `assemble` → `InvalidKinds`).
  - **Resume is exact only for `ReplayOnly`, or `RecordMisses` when every post-resume request hits the store** — never for `Live`. Check with `verify_snapshot` before `restore`; the driver also re-checks the manifest on every Decision, so a restore into an already-running simulation is caught. `merge_shards` is never called for you, and it changes `base_digest`.
- **Information structure:** a rule's default view is limited to opponents in **its own encounter** (`opponents()`, `opponent_history(id)` → `None` for anyone else) plus `X::view_for(me)`. The whole world is readable **only** through `ctx.omniscient()`, which drops the guarantee (and, during Decision, `held` may reflect activation order). Put any agent-visible extra information behind `view_for`.
- **User-defined matching state goes in `X`.** `MatchingState` is a closed enum (`None`, `RoundRobin { cursor }` for the built-in round-robin); a custom `Matching` reads its bookkeeping from `ctx.x()` and your own mechanism updates it via `GameWorld::x_mut()`.
- **Decision scope must fit the matching.** `DecisionScope::PerStep` (default) means one decision per agent per step, so every agent must hold **one role** per step. A matching that can tell up front rejects violations in `Matching::check` via `MatchContext::decision_scope()` (`RoundRobin`: `PerStep` with ≥ 3 agents or `both_orders(true)` → `GameError::InvalidMatching` from `assemble`); otherwise `game_decide` stops the step with `RuleError::AmbiguousRole` (also for `Held` agents). Use `PerAgentRole` or `PerEncounter` when agents sit in several encounters with different roles. Under those two scopes `held` is not written and `StepRecord::action` is `None` — read past actions from `LearnContext::outcomes()` or the pair history, not from step history.
- **`learn_encounter` call order is fixed.** In Reward, agents in ascending `AgentId`; per agent, `learn_encounter` once per own encounter in `EncounterId` order (only if `needs_encounter_learning()` returns `true`), then `learn_step`. Learning never receives an RNG. The built-in learning rules keep per-opponent state (`by_opponent`) under `PerEncounter` and update it in `learn_encounter`; under the other scopes they keep one `global` state and update it in `learn_step`.
- **Pair history is limited to current opponents.** `DecisionContext::pair_history(other)` returns `None` unless the pair history exists (some assigned kind's `needs_pair_history()` is `true`) **and** `other` is in `ctx.opponents()`; full access only via `ctx.omniscient().pair_history(a, b)`, which drops the information-structure guarantee. It is written by `game_play` after payoffs, so a decision never sees the current step. Assigning `MyopicBestResponse` enables it (its finer-scope modes read it).
- **Learning-rule cores live in the default build and depend on no `socsim-*` crate** (`socsim_games::learn` uses only `rand`, `serde`, `thiserror`). Keep it that way: the `DecisionRule` wrappers (`core`) adapt the cores to the world; do not move `socsim-core` types into `learn`.
- **Rules draw only from the engine stream.** Learning rules sample via `decide`'s `SimRng`, consumed in activation order then decision-unit order; probability sampling = one `gen::<f64>()` walked over cumulative probabilities; random ties = one `gen_range`. Deterministic rules and lowest-index ties consume nothing.
- **LLM decisions support `PerStep` only** (`assemble_with_llm` → `RuleError::Unsupported` for other scopes).
- Mechanisms you add after `assemble` run after the game mechanisms within each phase; a Reward-phase mechanism sees this step's `payoffs()`. `payoffs()` / `n_played()` are reset every PreStep — accumulate across steps yourself.
- **`game_metrics` is observation only.** It uses no RNG and writes nothing in the world except its own `MetricsState` (created only with `stop` or `MixedSource::PlayedCumulative`); policy states, held actions, plays and payoffs are untouched, so adding it, enabling `log_actions` / `log_plays`, or enabling `report_mixed` never changes a trajectory. Add one per simulation (there is a single `MetricsState`), built from the same game as the world (shape is re-checked every step). `game.play` records only encounters that were already materialized; logging never materializes an implicit path.
- **No NaN in the metric state of the world or in records.** An undefined metric column is omitted from the row, never written as NaN; a non-finite metric (or a non-finite payoff it reads) stops the step in `game_metrics` before the row is recorded; a non-finite aggregate value stops the step in `game_play` before the row enters the aggregate table; non-finite mixed reports are stored as `None`.
- **Reported mixes are post-learning.** `reported_mixed(agent, role)` after step `t` is the mix the decision of step `t + 1` will use (written at the end of Reward, after every agent learned), not the mix that produced step `t`'s action. `DecisionRule::mixed` must not mutate state or draw randomness (it takes `&state` and no RNG).
- **Aggregates only via `assemble_with_aggregates`.** Plain `assemble` and `assemble_with_llm` create no aggregate table (`aggregate_history()` is `None`, no `game.aggregate.*` columns). Rows are written in Interaction, so a decision sees completed previous steps only.
- **Population dynamics act on held agents only, synchronously, after learning.** `assemble_with` rejects a dynamic when any agent has a rule. Every next action is computed from the pre-update state into a buffer and swapped in at once (Moran writes exactly one entry); never update `held` in place agent by agent — it breaks order independence and lattice symmetry. The mechanism runs in Reward after `game_decide` and before mechanisms you add. **The one exception is `async_population_step`** (`assemble_async`): it is a different model, updates `held` in place one activated agent at a time by design, recomputes the payoffs it compares from the current `held` (never reuses the step's `world.payoffs()`), and is the only game mechanism registered. Do not imitate in place anywhere else, and do not add a synchronous dynamic, `game_match`, `game_decide` or `game_play` next to it.
- **PostStep sees two times at once.** After a dynamic, `payoffs()` / `n_played()` / `plays()` / step history describe the actions **played** this step, `held()` the **updated** actions of the next step. `game.played_share` (seats, before) ≠ `game.population_share` (agents, after). **Exception — `async_population_step`:** there is one time; payoffs, step history and `held()` all describe the actions after every update (`plays()` empty), and `played_share` / `population_share` are counted from the same `held`, differing only in denominator (seats vs agents) — equal when every agent has the same seat count (`WholePopulation`, torus, regular network), slightly different on a fixed-boundary lattice. Never read that difference as an update effect.
- **Dynamics draw only from the engine stream `[1]`** (step RNG), agents in ascending `AgentId`; they keep no state outside the world, so snapshot/resume is exact. Do not seed extra RNGs inside a dynamic or matching; use `[4]+` for your own initial placement streams.
- **Bounds for β and linear fitness come from the matching.** Prefer matchings that report `encounter_bounds`, or `PayoffAggregation::Mean`; a user-defined `OutcomeRule` cannot be bounded.
- **Do not read `world.plays()` on the implicit path** (it is empty); set `PlayOptions::materialize(true)` if you need the arena.
- **`report_mixed` is incompatible with `PerEncounter`** (`assemble` → `GameError::Metrics`): the learning rules' per-opponent states have no single mix to report.
- **Continuous rules respond simultaneously, to the previous step's history.** `DampedBestResponse` / `GradientAscent` read the other roles' actions from the step history (`opponent_history(j)`, last played action), never from peers' `held` — `game_decide` writes `held` in activation order, so reading it would turn the Jacobi update into an order-dependent Gauss–Seidel one and change the dynamics (Theocharis's instability is a property of the simultaneous iteration). A custom continuous rule must do the same; on the first step (no history) return `ctx.my_held()`.
- **Never use a result with `BrStatus != Converged` as an equilibrium.** `best_response_iteration` returns `MaxIter` with the last iterate when no damping converged; an oracle / golden-section result that is not `Converged` is a failure everywhere in the crate (`SolveError::NoBestResponse`, `RuleError::BestResponse`, `ContinuousEquilibrium::Solve` → `GameError::Metrics`). Keep the default damping and adaptive halving: undamped simultaneous best responses cycle in linear Cournot with ≥ 3 firms (Theocharis 1960). Do not tighten `tol` below ~1e-7 when best responses come from the golden-section search (√ε precision) — it ends in `MaxIter`.
- **Snapshot JSON assumes `serde_json`'s `float_roundtrip`.** Continuous actions persist in the world (`held`, step history, `ContinuousState::last`, the metrics convergence vector); without exact float parsing ~9% of `f64` values come back 1 ULP off and a resumed run diverges. `socsim-games` enables the feature on its `serde_json` dependency (Cargo unifies it build-wide); do not remove it, and keep exact round-trip if snapshots go through another serializer.

**`socsim-datasets` specifics**
- The crate **never vendors data**. The raw ANES Time-Series microdata is license-gated (needs a free electionstudies.org account + data-use agreement), so it is `Source::Manual` and is not auto-downloaded. CES 2022 Common Content is CC0 1.0 (public domain) on the Harvard Dataverse, so it is `Source::Dataverse` and **is** auto-downloaded. `fetch()` downloads only non-`Manual` sources into a consuming repo's gitignored `data/`.
